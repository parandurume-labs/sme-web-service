코드 없이 쓰는 더 간단한 대안

예약 좌석 관리가 필요 없다면 아래 서비스만으로도 시작할 수 있습니다.

  • Google Forms — 문의·신청서를 만들면 응답이 Google Sheets에 자동으로 쌓입니다.
  • Google Calendar 예약 일정 — 예약 가능한 시간을 열어 두면 손님이 직접 시간을 고르는 예약 페이지가 생깁니다. 기본 기능은 개인 계정에서도 쓸 수 있습니다.

이 템플릿은 여기에 더해 좌석 수에 따른 동시 예약 관리, 관리자 화면, 보안 기능을 제공합니다.

1단계: 내 업체 정보 입력하기

수정할 파일은 딱 2개입니다:

1 data/config.json — 업체 기본 정보

메모장이나 VS Code로 열어서 내 업체 정보로 바꿉니다:

항목설명예시
name업체 전체 이름"우리미용실 강남점"
shortName짧은 이름 (로고용)"우리미용실"
address주소"서울시 강남구 ..."
phone전화번호"02-1234-5678"
hours영업시간"09:00 - 18:00"
googleMapsUrlGoogle Maps 공유 링크"https://maps.app.goo.gl/..."
totalSeats동시 서비스 가능 수3 (의자 수)

2 data/services.json — 서비스 메뉴

서비스를 추가하거나 가격을 수정합니다. 각 서비스에 필요한 항목:

항목설명예시
id영문 고유 ID"mens-cut"
name서비스 이름"남성 커트"
price가격"15,000원"
duration소요시간 (분)30
description한 줄 설명"스타일 상담부터 마무리까지"
주의: duration 값은 예약 시간 충돌 계산에 사용됩니다. 실제 소요시간보다 약간 여유있게 설정하세요.

Google Maps 임베드 URL 구하는 방법

  1. Google Maps에서 내 업체를 검색합니다
  2. 공유 버튼을 클릭합니다
  3. "링크 복사" → googleMapsUrl에 붙여넣기
  4. "지도 퍼가기" → iframe 코드에서 src="..." 안의 URL만 복사 → googleMapsEmbed에 붙여넣기

2단계: Google 스프레드시트 만들기

1 새 스프레드시트 생성

sheets.google.com에서 "새 스프레드시트"를 만듭니다.

이름: 내 업체 문의/예약 (원하는 이름으로)

팁: 시트 헤더(열 제목)는 자동으로 생성됩니다. 빈 스프레드시트 그대로 두세요.

3단계: Google Apps Script 설정하기

이 단계가 가장 중요합니다. 아래 순서를 정확히 따라주세요.

1 Apps Script 편집기 열기

스프레드시트에서 확장 프로그램 → Apps Script 클릭

2 코드 붙여넣기

  1. 기본 코드(myFunction)를 모두 선택(Ctrl+A)하고 삭제
  2. 프로젝트의 google-apps-script.js 파일 내용을 전체 복사
  3. Apps Script 편집기에 붙여넣기
  4. 저장 (Ctrl+S)

3 웹앱으로 배포하기

  1. 우측 상단 배포 → 새 배포
  2. 유형: 웹 앱 선택
  3. 실행 사용자: 나
  4. 액세스 권한: 모든 사용자
  5. 배포 클릭 → 승인
  6. 표시된 웹앱 URL을 복사
매우 중요: 코드를 수정한 후에는 반드시 배포 관리에서 기존 배포를 새 버전으로 업데이트해야 합니다. 그렇지 않으면 옛 코드가 실행됩니다.

4 URL을 config.json에 입력

data/config.json을 열고 복사한 URL을 붙여넣습니다:

"api": {
  "googleAppsScriptUrl": "https://script.google.com/macros/s/여기에_URL_붙여넣기/exec"
}

5 스크립트 속성 설정 (비밀 키)

Apps Script 편집기에서:

  1. 좌측 프로젝트 설정 (톱니바퀴 아이콘)
  2. 아래로 스크롤 → 스크립트 속성
  3. 아래 속성들을 추가:
속성 이름값필수
RECAPTCHA_SECRET_KEYreCAPTCHA 비밀 키 (설정하면 모든 접수에 스팸 방지 확인이 필수가 됩니다)필수
CALENDAR_IDGoogle Calendar ID선택
ADMIN_KEY관리자 페이지 비밀번호 — 12자 이상, 다른 곳에서 쓰지 않는 값필수

관리자 키를 5번 연속 틀리면 15분 동안 로그인이 잠기고 알림 메일이 옵니다.

6 개인정보 자동 파기 켜기 (최초 1회)

  1. Apps Script 편집기 상단의 함수 목록에서 setupSecurityTriggers 선택
  2. 실행 클릭 → 권한 승인

이제 매일 새벽 4시에 보유기간(기본 365일)이 지난 예약·문의가 자동으로 삭제됩니다. 기간은 코드의 retentionDays와 웹사이트 동의서 문구를 함께 맞춰 주세요.

4단계: reCAPTCHA 스팸 방지 설정하기

고객이 폼 작성
→
reCAPTCHA
"로봇이 아닙니다" 체크
→
스팸이 아닌 경우만
서버에 전송

1 reCAPTCHA 사이트 등록

  1. Google reCAPTCHA Admin 접속
  2. + 클릭 → 새 사이트 등록
  3. 유형: reCAPTCHA v2 → "체크박스"
  4. 도메인: localhost 와 username.github.io 추가
  5. 제출

2 키 적용

키 종류어디에 넣나요?
사이트 키 (공개)data/config.json의 recaptcha.siteKey
비밀 키 (비공개)Apps Script 스크립트 속성의 RECAPTCHA_SECRET_KEY
보안 주의: 비밀 키는 절대 config.json이나 코드에 넣지 마세요. 반드시 스크립트 속성에만 저장합니다.

5단계: 로컬에서 테스트하기

1 로컬 서버 실행

터미널(명령 프롬프트)에서:

cd sme-web-service
npx serve .

브라우저에서 http://localhost:3000 접속

주의: index.html을 더블클릭해서 열면 (file:// 프로토콜) reCAPTCHA와 JSON 로드가 작동하지 않습니다. 반드시 npx serve를 사용하세요.

2 테스트 항목

  • 서비스 카드가 6개(또는 설정한 수만큼) 표시되는가
  • Google Maps 지도가 보이는가
  • 예약: 날짜 선택 → 서비스 선택 → 빈 시간대가 표시되는가
  • reCAPTCHA 체크박스가 보이는가
  • 모바일 화면 (브라우저 창 줄이기)에서 햄버거 메뉴가 동작하는가
  • 문의 제출 시 Google Sheets에 데이터가 저장되는가
  • 예약 제출 시 Google Calendar에 이벤트가 생성되는가
  • 이메일 알림이 도착하는가

사장님이 직접 해야 할 일

1 Google 계정 잠그기 (가장 중요)

  • Google 계정 보안에서 2단계 인증 켜기 (가능하면 패스키 또는 휴대폰 확인 방식)
  • 복구 전화번호와 복구 이메일 등록 — 계정을 잃어버렸을 때 되찾는 유일한 길입니다
  • 보안 진단을 열어 노란색·빨간색 경고 모두 해결
  • 다른 사이트와 같은 비밀번호 쓰지 않기
  • 매장 업무용 Google 계정을 개인 계정과 따로 만드는 것을 권장

2 스프레드시트 공유 점검

  • 스프레드시트 오른쪽 위 공유 → 일반 액세스가 "제한됨"인지 확인 ("링크가 있는 모든 사용자"면 즉시 변경)
  • 직원에게 보여 줘야 한다면 필요한 사람만, 가능하면 뷰어 권한으로 추가
  • 직원이 그만두면 그날 바로 공유 목록에서 삭제
  • 타사 앱 연결에서 모르는 앱의 접근 권한 삭제
참고: Apps Script 배포의 "모든 사용자" 권한은 웹사이트가 스크립트를 호출할 수 있다는 뜻입니다. 스프레드시트가 공개된다는 뜻이 아닙니다.

3 관리자 키와 주소 관리

  • ADMIN_KEY는 12자 이상, 다른 곳에서 쓰지 않는 값으로 정하기 (예: 단어 3~4개 조합)
  • 관리자 키를 메신저나 문자로 보내지 않기. 직원에게 알려 줬다면 그만둘 때 바꾸기
  • "관리자 로그인 실패 반복" 알림 메일을 받았는데 본인이 아니라면 바로 ADMIN_KEY 변경
  • 공용 PC에서는 관리자 페이지 사용 후 꼭 로그아웃

4 개인정보 관리 (개인정보보호법)

  • 웹사이트에 개인정보 처리방침 게시 — 개인정보 포털의 작성 도구를 활용할 수 있습니다
  • 3단계 6번의 setupSecurityTriggers를 실행해 자동 파기 켜기
  • 보유기간을 바꾸면 코드의 retentionDays와 웹사이트 동의서 문구를 함께 고치기
  • 시트를 엑셀·CSV로 내려받았다면 쓴 뒤 PC에서 삭제하기
  • 알림 메일에도 고객 정보가 들어 있으므로 휴대폰 화면 잠금 필수

사고가 났을 때

상황바로 할 일
Google 계정이 해킹된 것 같음 비밀번호 변경 → 기기 활동에서 모르는 기기 로그아웃 → 2단계 인증 확인
→ 스프레드시트 공유 목록 점검 → ADMIN_KEY 변경
관리자 키가 유출됨 스크립트 속성에서 ADMIN_KEY를 새 값으로 변경 (재배포 불필요)
스팸 예약이 계속 들어옴 reCAPTCHA 비밀 키 설정 확인
→ 그래도 계속되면 배포 관리에서 기존 배포를 보관 처리하고 새 배포를 만든 뒤 config.json의 주소 교체
고객 정보가 밖으로 새어 나간 것 같음 위 조치로 추가 유출을 막고, 개인정보침해 신고센터(국번 없이 118)에 상담하세요.
유출 규모와 종류에 따라 고객 통지와 기관 신고 의무(72시간 이내)가 생길 수 있습니다.

문제 해결

증상원인해결 방법
서비스 카드가 안 보임 file://로 열었을 때 JSON 로드 실패 npx serve . 으로 로컬 서버 실행
reCAPTCHA가 안 보임 사이트 키 미설정 또는 file:// 프로토콜 config.json에 사이트 키 입력 + 로컬 서버 사용
"개인정보 동의가 필요합니다" 오류가 뜨거나 시간 조회가 안 됨 웹사이트는 새 버전인데 Apps Script는 옛 버전으로 배포됨 배포 관리 → 기존 배포 수정 → 새 버전 선택 → 배포
빈 시간대 조회가 안 됨 API URL 미설정 또는 Apps Script 접근 권한 문제 config.json의 API URL 확인 + 배포 시 "모든 사용자" 접근 권한 확인
같은 시간에 중복 예약됨 스프레드시트 헤더에 "좌석" 열 없음 스프레드시트의 예약내역 시트 헤더에 "좌석", "상태" 열 추가
관리자 페이지 로그인 안 됨 ADMIN_KEY 미설정 또는 12자 미만 Apps Script 프로젝트 설정 → 스크립트 속성에 12자 이상의 ADMIN_KEY 추가
"로그인 시도가 너무 많습니다" 관리자 키를 5회 연속 틀림 15분 뒤 다시 시도. 본인이 아니라면 ADMIN_KEY 변경
"요청이 너무 많습니다" 10분 안에 접수가 몰려 요청 제한에 걸림 잠시 후 다시 시도. 정상 손님이 자주 막힌다면 코드의 rateLimit 값을 늘리기

최종 체크리스트

배포 전 모든 항목을 확인하세요:

업체 정보

  • config.json에 업체명, 주소, 전화번호 입력
  • config.json에 영업시간 입력
  • config.json에 Google Maps URL 입력
  • services.json에 서비스 메뉴와 가격 입력
  • services.json에 각 서비스의 소요시간(duration) 설정

백엔드 연동

  • Google Apps Script 코드 붙여넣기 완료
  • 웹앱 배포 완료 ("모든 사용자" 접근 권한)
  • config.json에 API URL 입력
  • 스크립트 속성에 RECAPTCHA_SECRET_KEY 설정
  • 스크립트 속성에 ADMIN_KEY 설정 (12자 이상)
  • setupSecurityTriggers 실행 (개인정보 자동 파기)

보안

  • Google 계정 2단계 인증 + 복구 연락처 등록
  • 스프레드시트 일반 액세스 "제한됨" 확인
  • 개인정보 처리방침 게시

reCAPTCHA

  • reCAPTCHA v2 사이트 등록 완료
  • config.json에 사이트 키 입력
  • 도메인에 localhost + GitHub Pages 도메인 등록

테스트

  • 문의 폼 제출 → Sheets 저장 + 이메일 알림 확인
  • 예약 폼 제출 → Sheets 저장 + Calendar 이벤트 + 이메일 확인
  • 중복 예약 방지 동작 확인
  • 관리자 페이지 (admin.html) 로그인 + 데이터 조회 확인
  • 모바일 화면 확인
